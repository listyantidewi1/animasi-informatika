# F11.10 Proyek: Aplikasi Berbasis Data Terbuka — satu baris per potongan narasi: id<TAB>teks. Simpan suaranya sebagai <id>.mp3
intro1	Halo, kelas sebelas! Aku Kiko. Di F11.5 kita memutuskan bulan kemah dengan lembar kerja. Kali ini OSIS minta aplikasi kecil yang bisa dipakai lagi tiap tahun. Setelah menonton, kamu bisa membuat program Python yang mengolah data terbuka.
intro2	Proyek ini menggabungkan dua episode: alur pengembangan dari F11.1, dan siklus data terbuka dari F11.5. Hasilnya: program Cek Bulan Kemah, sekitar tiga puluh baris Python, dengan README dan test case.
intro3	Episode ini melanjutkan F11.1 tentang alur pengembangan dan F11.5 tentang data terbuka. Pastikan juga sudah lancar fungsi dan perulangan dari F11.2. Kalau belum, tonton dulu, ya.
play1	Main dulu. Guru membagikan dua puluh kartu data hujan harian, beberapa rusak: kosong, angka 999, atau kembar. Satu orang jadi fungsi bersihkan, satu jadi fungsi rangkum, satu jadi fungsi rekomendasi. Kartu berpindah tangan.
play2	Tiap orang hanya mengerjakan tugasnya, lalu menyerahkan hasil ke orang berikutnya. Kalau hasil akhirnya salah, kita tahu di tangan siapa salahnya. Itulah gunanya memecah program menjadi fungsi-fungsi kecil.
s1a	Tahap satu: kebutuhan. Wawancara ketua OSIS. Wajib: baca file data hujan dari portal terbuka, abaikan data rusak, tampilkan jumlah hari hujan per bulan, dan sebutkan bulan terbaik. Tambahan: grafik, beberapa kota.
s1b	Jaga lingkupnya kecil. Versi satu titik nol hanya untuk satu kota dan satu file CSV. Proyek kelas yang selesai dan jalan jauh lebih berharga daripada proyek besar yang berhenti di tengah. Tambahan menunggu versi berikutnya.
q1	Cek pemahaman. Waktu proyek tiga minggu. Fitur mana yang masuk versi satu titik nol: grafik animasi tiga dimensi, membaca file CSV dan menyebut bulan terbaik, atau data seluruh kota di Indonesia? Pikirkan dulu.
q1a	Jawabannya: membaca file CSV dan menyebut bulan terbaik. Itu inti kebutuhan OSIS. Grafik dan kota lain boleh menyusul setelah versi pertama jalan dan diuji.
s2a	Tahap dua: desain alur data. Empat kotak berurutan: baca file, bersihkan, rangkum per bulan, rekomendasikan. Panah di antaranya adalah data yang diserahkan: daftar baris mentah, daftar bersih, lalu jumlah per bulan.
s2b	Pilih struktur datanya. Tiap baris CSV menjadi list berisi tanggal dan curah hujan. Ringkasan per bulan cocok disimpan di dictionary: kuncinya nama bulan, nilainya jumlah hari hujan. Desain ini lalu ditulis sebagai pseudocode.
q2	Cek pemahaman. Kamu perlu menyimpan jumlah hari hujan untuk tiap nama bulan. Struktur data yang paling cocok: satu variabel integer, list tanpa nama, atau dictionary dengan nama bulan sebagai kunci? Pikirkan dulu.
q2a	Jawabannya: dictionary dengan nama bulan sebagai kunci. Kita bisa langsung menulis hujan per bulan Agustus, tanpa menghafal Agustus ada di posisi ke berapa.
s3a	Bagian dua. Tahap tiga: implementasi, satu fungsi demi satu. Fungsi baca data membuka file dengan modul csv bawaan Python, melewati baris judul, dan mengembalikan list baris. Jalankan, cetak tiga baris pertama, baru lanjut.
s3b	Fungsi bersihkan memeriksa tiap baris: lewati yang kosong, lewati kode 999, lewati tanggal yang sudah pernah muncul, dan ubah teks angka menjadi float. Fungsi rangkum menghitung hari hujan per bulan ke dalam dictionary.
q3	Cek pemahaman. Satu baris CSV berisi curah hujan 999, kode untuk tidak terukur. Apa yang dilakukan fungsi bersihkan: menghitungnya sebagai hujan deras, melewatinya dan mencatat, atau menghentikan program? Pikirkan dulu.
q3a	Jawabannya: melewatinya dan mencatat jumlah baris yang dilewati. Metadata bilang 999 berarti tidak terukur, bukan hujan. Program tetap jalan, dan laporannya jujur.
s4a	Tahap empat: pengujian. Tiap fungsi diuji dengan test case kecil yang hasilnya sudah diketahui. Bersihkan tiga baris, satu kosong, satu 999, satu baik: harapannya satu baris tersisa. Rangkum dua hari hujan di Agustus: harapannya dua.
s4b	Tahap lima dan enam: rilis dan pemeliharaan. README menjelaskan cara menjalankan, format file, dan sumber datanya. OSIS memakainya, lalu minta data tahun baru dan grafik: versi satu titik satu, dengan catatan perubahan.
q4	Cek pemahaman. Fungsi rangkum diberi dua baris hujan di bulan Agustus dan satu baris kering. Hasil yang diharapkan untuk Agustus: satu, dua, atau tiga? Pikirkan dulu.
q4a	Jawabannya: dua. Hari kering tidak dihitung sebagai hari hujan. Kalau programmu menjawab tiga, ada bug di kondisi perbandingannya: periksa lebih dari nol.
s5a	Sekarang proyek kelompokmu. Pilih satu set data terbuka tentang daerahmu: cuaca, kualitas udara, jumlah pengunjung perpustakaan. Bagi peran seperti di F11.1: analis, desainer, pengembang, penguji, dan penulis README.
s5b	Yang dinilai bukan hanya programnya: dokumen kebutuhan, gambar alur data, kode berfungsi kecil yang terbaca, tabel test case, README, catatan perubahan, dan presentasi lima menit dengan demo langsung.
s6a	Sekarang giliranmu. Di halaman latihan: perakit program, susun fungsi dan urutannya menjadi program utuh; penguji fungsi, tebak hasil tiap test case lalu jalankan; dan pemeriksa README, lengkapi bagian yang hilang.
s6b	Lalu di komputer: ketik program Cek Bulan Kemah, jalankan dengan file contoh, tambahkan satu test case milikmu, dan tulis README-nya. Itu bekal proyek akhir di kelas dua belas.
recap	Tiga hal untuk diingat. Satu: proyek kecil, alur lengkap, dari kebutuhan sampai rilis. Dua: satu fungsi satu tugas, baca, bersihkan, rangkum, rekomendasikan. Tiga: uji tiap fungsi dengan test case, lalu rilis dengan README.
outro	Sampai jumpa di kelas dua belas: kita mulai dengan jembatan, memeriksa bekal fungsi, list, dan perulangan, sebelum masuk ke struktur data yang lebih kompleks. Sampai jumpa!
