Bab sembilan, uji dan online. Ini bab terakhir. Di akhir bab ini, aturan-aturan penting kita dijaga oleh test otomatis, dan SiLapor berjalan di server sungguhan dengan HTTPS.

Sepanjang video, kita menguji dengan cara mengeklik sendiri. Cara itu lama-lama melelahkan, dan suatu hari pasti ada yang terlewat. Test otomatis adalah kode yang memeriksa kode. Kita tidak perlu menguji semuanya. Kita cukup menguji aturan yang kalau rusak, akibatnya berat.

Test pertama menjaga privasi. Kita membuat laporan milik Lina, lalu berpura-pura menjadi Dimas dengan actingAs, dan membuka laporan itu. Harapannya, server menjawab forbidden. Baris RefreshDatabase membuat setiap test mulai dari database yang bersih. Database itu terpisah dan hanya hidup di memori, jadi data kita yang sungguhan tidak tersentuh.

Test kedua menjaga alur status, yaitu laporan yang selesai tidak bisa kembali menjadi baru. Test ketiga menjaga upload, yaitu berkas PHP harus ditolak. Di GitHub, ada lima test lain dengan pola yang sama. Jalankan php artisan test. Semuanya hijau.

Apakah test ini benar-benar berguna? Kita buktikan. Hapus baris Gate authorize di controller, seolah-olah seseorang tidak sengaja menghapusnya saat merapikan kode. Jalankan test lagi. Merah, dan pesannya menunjuk tepat ke aturan yang rusak. Kembalikan baris itu, dan test hijau lagi. Mulai sekarang, biasakan menjalankan test sebelum commit.

Sekarang kita buat online. Kamu butuh sebuah server Linux, bisa VPS sewaan atau komputer server di sekolah, dan sebuah nama domain. Susunannya seperti ini. Nginx menerima request dari internet, lalu meneruskannya ke PHP-FPM yang menjalankan Laravel, dan Laravel berbicara dengan MySQL.

Masuk ke server dengan ssh. Pasang Nginx, PHP beserta ekstensinya, MySQL, Composer, dan Git lewat apt. Perintah lengkapnya ada di README, di alamat GitHub yang tampil di layar. Lalu ambil kodenya dengan git clone ke folder var garis miring www, dan jalankan composer install minus minus no dev, supaya alat untuk pengembangan tidak ikut terpasang di server.

Berikutnya, berkas titik env untuk server. Salin dari titik env titik example, lalu ubah tiga hal. APP_ENV menjadi production. APP_DEBUG menjadi false. Lalu bagian database, dengan pengguna dan kata sandi yang kita buat di server, sama seperti di bab satu. Setelah itu, jalankan php artisan key:generate, lalu migrate minus minus force, lalu db:seed untuk kategori dan akun admin. Jangan lupa mengganti kata sandi admin.

Laravel perlu menulis ke dua folder, yaitu storage, dan cache di dalam folder bootstrap. Kita jadikan dua folder itu milik www-data, yaitu pengguna yang menjalankan PHP di server. Cukup dua folder itu, dan cukup untuk satu pengguna itu.

Di pengaturan Nginx, ada satu baris yang paling penting, yaitu root. Arahkan root ke folder public, bukan ke folder proyeknya. Kalau root menunjuk ke folder proyek, berkas titik env bisa diunduh siapa saja, lengkap dengan kata sandi database di dalamnya.

Aplikasi yang punya halaman login wajib memakai HTTPS, supaya kata sandi tidak melintas di jaringan sebagai teks biasa. Sertifikatnya gratis dari Let's Encrypt. Pasang certbot, jalankan certbot minus minus nginx, lalu ikuti pertanyaannya. Certbot juga memperpanjang sertifikat itu secara otomatis.

Dua hal terakhir. Jalankan php artisan optimize, supaya pengaturan dan route disimpan di cache. Lalu siapkan backup. Dengan cron, jadwalkan mysqldump setiap malam, dan salin juga folder foto di storage. Simpan hasilnya di tempat lain, karena backup yang berada di server yang sama akan ikut hilang kalau servernya rusak.

Cek kerjaan AI, yang terakhir. Setelah dipasang di server, muncul error permission denied. Kita bertanya kepada AI, dan sarannya dua. Jalankan chmod minus R tujuh tujuh tujuh pada folder proyek, lalu ubah APP_DEBUG menjadi true supaya error-nya terlihat. Error-nya memang hilang. Apa bahayanya? Pikirkan dulu.

Tujuh tujuh tujuh berarti siapa pun di server itu boleh mengubah semua berkas aplikasi kita, termasuk kodenya. Lalu, dengan debug true, setiap error menampilkan isi dapur aplikasi kepada pengunjung, mulai dari potongan kode, susunan folder, sampai isi pengaturan. Saran itu menghilangkan gejalanya, tetapi membuka pintunya lebar-lebar.

Selesai. Kita berangkat dari komputer kosong, mengobrol dengan Pak Hendra, merancang empat tabel, lalu membangun login, upload yang aman, alur status, dan hak akses, sampai aplikasinya online. Yang lebih penting, sekarang kamu tahu apa saja yang perlu diperiksa saat AI menyodorkan kode. Daftar periksanya ada di deskripsi. Tantangan terakhirmu, kerjakan satu tantangan dari bab mana pun, lalu ceritakan hasilnya di kolom komentar. Sampai jumpa di proyek berikutnya.
