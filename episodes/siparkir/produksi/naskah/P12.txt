Bab dua belas, membuat aplikasi online. Supaya bisa dibuka dari pos parkir, aplikasi ini harus berjalan di server yang menyala terus. Kita memakai Docker, supaya server tidak perlu dipasangi PHP dan MySQL satu per satu. Di akhir bab, SiParkir bisa dibuka lewat alamat HTTPS.

Docker membungkus sebuah program beserta semua kebutuhannya ke dalam satu kemasan, yang disebut image. Image yang sedang berjalan disebut container. Kita butuh dua container. Yang pertama berisi aplikasi Laravel kita, dijalankan oleh FrankenPHP, yaitu server web yang sudah menyatu dengan PHP. Yang kedua berisi MySQL. Keduanya diatur oleh satu berkas bernama compose titik yaml.

Kita tulis Dockerfile, yaitu resep untuk membuat image aplikasi kita. Baris FROM memilih image dasar FrankenPHP dengan PHP delapan titik tiga. Baris berikutnya memasang ekstensi untuk MySQL. Lalu Composer disalin, kode kita disalin ke folder app, dan composer install memasang pustakanya tanpa alat pengembangan. Berkas titik dockerignore memastikan titik env dan folder vendor dari laptop tidak ikut tersalin.

Sekarang compose titik yaml. Layanan app dibuat dari Dockerfile tadi, dan membuka port delapan puluh dan empat ratus empat puluh tiga. Variabel SERVER_NAME berisi nama domain kita. Begitu domain itu diisi, FrankenPHP mengurus sertifikat HTTPS-nya sendiri. DB_HOST kita isi db, yaitu nama layanan kedua, karena di dalam Docker setiap layanan saling memanggil dengan namanya. Layanan db memakai image MySQL, dan datanya disimpan di volume, supaya tidak hilang ketika container dibuat ulang.

Simpan dengan commit, lalu kirim ke GitHub dengan git push. Sekarang kita pindah ke server. Aku menyewa sebuah VPS dengan Ubuntu, dan nama domainnya sudah diarahkan ke alamat IP server itu. Cara menyewa server dan mengarahkan domain ada di README, di alamat GitHub yang tampil di layar ini. Masuk ke server dengan ssh, lalu pasang Docker dengan skrip resminya dari get.docker.com.

Ambil kodenya dengan git clone, lalu masuk ke foldernya. Salin titik env titik example menjadi titik env, lalu ubah empat hal. APP_ENV menjadi production. APP_DEBUG menjadi false. APP_DOMAIN diisi nama domain. Dan DB_PASSWORD diisi kata sandi baru yang panjang, bukan kata sandi latihan kita. Kunci aplikasinya kita buat dengan docker compose run, diikuti php artisan key:generate, minus minus show, lalu hasilnya ditempel ke APP_KEY.

Jalankan docker compose up, minus d, minus minus build. Docker membuat image, lalu menyalakan kedua container di latar belakang. Setelah itu, buat tabel dan data awalnya dengan docker compose exec app, diikuti php artisan migrate, minus minus seed, minus minus force. Buka domainnya di browser. Gembok HTTPS muncul, dan halaman masuk SiParkir tampil. Langkah pertama setelah online adalah mengganti kata sandi keempat akun contoh, karena kata sandi itu tertulis terbuka di GitHub.

Satu kebiasaan lagi, yaitu cadangan. Perintah mysqldump di dalam container db menyalin seluruh isi database ke satu berkas. Jalankan setiap malam, dan simpan salinannya di luar server. Aplikasi parkir menyimpan catatan uang, jadi kehilangan datanya berarti kehilangan bukti.

Cek kerjaan AI yang terakhir. Kita meminta AI menyiapkan berkas titik env untuk server. Inilah hasilnya, dan aplikasinya langsung berjalan. Menurutmu, baris mana yang berbahaya? Pikirkan dulu.

Barisnya adalah APP_DEBUG sama dengan true. Dengan pengaturan itu, setiap kali terjadi error, Laravel menampilkan halaman penuh rincian kepada siapa pun yang membukanya. Isinya potongan kode, letak berkas di server, query yang sedang dijalankan, dan nama database kita. Bagi kita itu alat bantu, tetapi bagi penyerang itu peta. Di server, APP_DEBUG harus false, supaya pengunjung hanya melihat halaman maaf yang sederhana.

Kita sudah sampai di ujung. Dari folder kosong, kita memahami kebutuhan, merancang enam tabel, menulis rumus tarif yang dijaga test, mencetak struk, membuat rekap yang benar, lalu membuatnya online. Kamu juga sudah melihat dua belas kesalahan yang lazim muncul dari AI, dan sekarang kamu tahu cara menemukannya. Daftar periksanya ada di README, dan boleh kamu pakai setiap kali menerima kode dari AI.

Tantangan terakhirmu, bangun ulang aplikasi ini untuk kebutuhan di sekitarmu, misalnya penitipan helm, sewa lapangan, atau peminjaman alat. Tanyakan aturannya langsung kepada orangnya, tulis test-nya dulu, dan jangan langsung percaya pada hasil AI sebelum kamu memeriksanya.
