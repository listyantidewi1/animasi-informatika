Bab tiga belas, online. Di akhir bab ini, kamu tahu cara menaruh SiPinjam di server sungguhan, dengan alamat sendiri, gembok HTTPS, dan cadangan data setiap malam.

Ada tiga hal yang perlu disiapkan. Pertama, server Linux, yang bisa berupa VPS sewaan, atau komputer di ruang server sekolah. Kedua, nama domain untuk alamatnya. Ketiga, empat program di server itu, yaitu Nginx sebagai penerima tamu, PHP FPM yang menjalankan kode PHP kita, MySQL, dan Git. Perintah lengkap untuk memasangnya ada di README, di alamat GitHub yang tampil di layar ini.

Di server, langkahnya mirip dengan bab satu. Kita mengambil kode dengan git clone. Kita membuat database dan penggunanya, kali ini dengan kata sandi yang panjang dan acak. Kita menjalankan ketiga berkas SQL. Lalu kita menyalin titik env titik example menjadi titik env, mengisi kata sandinya, dan mengubah APP_DEBUG menjadi false.

Sekarang pengaturan Nginx, yang kita simpan di folder deploy, nginx titik conf. Baris root adalah baris terpenting, dan ia menunjuk ke folder public, bukan ke folder proyek. Blok location untuk berkas PHP meneruskan permintaan ke PHP FPM. Blok terakhir menolak semua berkas yang namanya diawali titik.

Untuk HTTPS, kita memakai Certbot, yang memberi sertifikat gratis dari Let's Encrypt dan memperpanjangnya sendiri. Tanpa HTTPS, kata sandi yang diketik siswa di WiFi sekolah bisa dibaca orang lain. Terakhir, cadangan. Perintah mysqldump menyalin seluruh database, termasuk prosedur dan trigger, menjadi satu berkas. Kita jadwalkan dengan cron supaya berjalan setiap pukul dua pagi. Dan ingat, cadangan yang belum pernah dicoba dipulihkan belum bisa disebut cadangan.

Cek kerjaan AI. Ini pengaturan server yang disarankan AI supaya cepat jalan. Root menunjuk ke folder proyek, bukan ke public, dan APP_DEBUG dibiarkan true. Situsnya langsung bisa dibuka. Apa lagi yang ikut bisa dibuka? Pikirkan dulu.

Kita buktikan di laptop. Server ini kita jalankan dari folder proyek, seperti saran AI tadi. Lalu kita minta alamat garis miring titik env. Seluruh isinya keluar, termasuk kata sandi database. Siapa pun di internet bisa melakukan hal yang sama, dan robot pencari celah mencoba alamat ini setiap hari. Lalu, dengan debug true, setiap error menampilkan nama berkas dan nomor baris kepada publik. Itulah alasan folder public kita pisahkan sejak bab satu.

Kita sudah sampai di ujung. Kamu sudah memasang alat, mewawancarai pemakai, merancang tujuh tabel, menulis function, stored procedure, dan trigger, membangun halaman untuk tiga peran, menguji, dan menyiapkan server. Yang lebih penting, kamu sudah tiga belas kali mencari kesalahan di kode yang kelihatannya benar. Itulah keahlian yang membuat AI menjadi asisten yang berguna di tanganmu. Sebagai tantangan, tambahkan fitur perpanjangan pinjaman, lengkap dengan aturannya di database. Seluruh kode ada di GitHub, di alamat yang tampil di layar ini.
