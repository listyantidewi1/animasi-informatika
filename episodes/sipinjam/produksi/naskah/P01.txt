Bab satu, persiapan. Di akhir bab ini, PHP dan MySQL sudah berjalan di komputermu, dan halaman pertama SiPinjam tampil di browser. Aku menganggap komputermu masih kosong, jadi kita pasang semuanya satu per satu. Kalau XAMPP, VS Code, dan Git sudah terpasang, silakan lompat ke bagian membuat database lewat cap waktu di deskripsi.

Alat pertama adalah XAMPP. Paket gratis ini memasang PHP dan database MySQL sekaligus. Buka apachefriends titik org, unduh versi untuk Windows, lalu jalankan penginstalnya. Di halaman Select Components, pastikan MySQL dan PHP tercentang. Biarkan folder pemasangannya di C, xampp, lalu tekan Next sampai Finish. Setelah itu, buka XAMPP Control Panel, lalu tekan tombol Start di baris MySQL sampai namanya berwarna hijau. Database yang dibawa XAMPP sebenarnya bernama MariaDB, yaitu kembaran MySQL, sehingga beberapa pesan di layarmu bisa sedikit berbeda dari punyaku. Untuk Mac dan Linux, cara memasangnya ada di README, di alamat GitHub yang tampil di layar ini.

Ada satu langkah yang sering terlewat. Windows belum tahu letak program php dan mysql, jadi kita perlu memberitahunya. Tekan tombol Windows, ketik environment, lalu buka Edit the system environment variables. Klik tombol Environment Variables, pilih baris Path, lalu klik Edit. Tambahkan dua baris baru, yaitu folder php dan folder mysql bin di dalam xampp, persis seperti di layar. Lalu tekan OK di semua jendela.

Alat kedua adalah Git, untuk menyimpan riwayat kode. Unduh dari git-scm.com, lalu pasang dengan pilihan bawaannya. Di Windows, Git membawa terminal bernama Git Bash. Alat ketiga adalah VS Code, dari code.visualstudio.com. Setelah terpasang, buka panel terminal lewat menu Terminal, New Terminal. Klik panah kecil di samping tanda tambah, lalu pilih Git Bash. Pakailah terminal ini, supaya perintah yang kamu ketik sama persis dengan yang kuketik.

Sekarang kita periksa. Ketik php minus minus version, lalu mysql minus minus version, dan terakhir git minus minus version. Kalau ketiganya menjawab dengan nomor versi, semua alat sudah siap. Kalau ada yang menjawab command not found, artinya langkah Path tadi belum terbaca. Tutup VS Code, buka lagi, lalu coba sekali lagi.

Sekarang kita siapkan folder proyeknya. Buat folder bernama sipinjam di tempat yang mudah kamu temukan, misalnya di Documents, lalu buka di VS Code lewat menu File, Open Folder. Di dalamnya, kita buat tiga folder. Folder public berisi halaman yang boleh dibuka dari browser. Folder app berisi kode yang tidak boleh dibuka langsung. Folder database berisi semua SQL kita. Pemisahan ini kelihatannya sepele, tetapi di bab terakhir, ia menyelamatkan kata sandi kita.

Berikutnya, database. Kita masuk ke MySQL sebagai root dengan perintah mysql minus u root. Di XAMPP, root belum punya kata sandi, jadi kita langsung masuk. Pertama, kita membuat database bernama sipinjam. Lalu kita membuat pengguna database khusus untuk aplikasi ini, juga bernama sipinjam, dengan kata sandinya sendiri. Terakhir, kita memberinya lima hak saja atas database sipinjam, yaitu membaca, menambah, mengubah, dan menghapus baris, serta menjalankan prosedur. Ia tidak boleh menghapus tabel, dan tidak bisa menyentuh database lain.

Sekarang kita buat berkas bernama titik env di folder utama. Berkas ini menyimpan pengaturan yang berbeda di setiap komputer, termasuk kata sandi. Baris DB_HOST berisi alamat database, dan satu dua tujuh, titik nol, titik nol, titik satu berarti komputer ini sendiri. DB_PORT adalah nomor pintunya, dan bawaan MySQL adalah tiga tiga nol enam. DB_NAME, DB_USER, dan DB_PASS berisi nama database, pengguna, dan kata sandi yang baru kita buat. Baris terakhir, APP_DEBUG, kita isi true selama masih belajar, supaya pesan error tampil di layar.

Berkas titik env tidak boleh ikut ke GitHub, karena siapa pun yang membacanya akan tahu kata sandi database kita. Jadi kita buat berkas titik gitignore, lalu menulis titik env di dalamnya. Sebagai gantinya, kita sediakan titik env titik example, yaitu contoh dengan kata sandi yang dikosongkan. Kalau nanti kamu mengambil proyek ini dari GitHub, salin titik env titik example menjadi titik env, lalu isi kata sandinya.

Sekarang kita uji semuanya dengan satu halaman kecil. Buat berkas index titik php di dalam folder public. Baris pertama membaca berkas titik env menjadi array. Baris kedua membuka sambungan ke MySQL lewat PDO, yaitu cara resmi PHP berbicara dengan database. Baris ketiga bertanya kepada MySQL, versi berapa dirimu, lalu menampilkan jawabannya.

Jalankan php minus S, localhost titik dua delapan ribu, minus t public. Perintah ini menyalakan server bawaan PHP, dan minus t public berarti hanya isi folder public yang bisa dibuka dari browser. Sekarang buka localhost titik dua delapan ribu di browser. Halaman kita muncul, lengkap dengan versi MySQL, jadi PHP dan database sudah tersambung. Kalau yang muncul Access denied, artinya nama pengguna atau kata sandi di titik env belum cocok. Server ini berjalan selama terminalnya terbuka, dan untuk menghentikannya, tekan Control C.

Aplikasi ini nanti dipakai dari HP, jadi kita coba dari sekarang. Hentikan servernya, lalu jalankan lagi dengan alamat nol, titik nol, titik nol, titik nol, supaya ia menerima sambungan dari perangkat lain. Cari alamat IP laptopmu dengan perintah ipconfig, di baris IPv4 Address. Pastikan HP dan laptop memakai WiFi yang sama, lalu ketik alamat IP itu di browser HP, diikuti titik dua delapan ribu. Kalau Windows bertanya soal firewall, pilih Allow access.

Cek kerjaan AI. Kalau kita meminta AI membuatkan koneksi database, hasilnya sering seperti ini. Penggunanya root, kata sandinya kosong, dan semuanya ditulis langsung di dalam kode. Di laptopmu, kode ini berjalan lancar. Apa akibatnya kalau kode ini dipakai di server sungguhan? Pikirkan dulu.

Ada dua masalah. Pertama, root adalah pemilik seluruh database di server itu. Kalau aplikasi ini dibobol, penyerang mendapat semua database, bukan hanya sipinjam. Kedua, kata sandi yang ditulis di dalam kode akan ikut ke GitHub, dan semua orang bisa membacanya. Itulah sebabnya kita membuat pengguna khusus dan berkas titik env. Sekarang kita simpan titik awal ini di Git. Ketik git init, git add titik, lalu git commit dengan pesan proyek awal. Alat sudah siap, tetapi kita belum akan menulis kode, karena kita belum tahu apa yang sebenarnya dibutuhkan lab. Di bab berikutnya, kita bertanya langsung kepada Pak Yusuf.
