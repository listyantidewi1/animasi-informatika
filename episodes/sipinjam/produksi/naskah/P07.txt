Bab tujuh, kerangka PHP. Di akhir bab ini, PHP kita tersambung ke database dengan cara yang aman, dan daftar alat tampil di browser.

Kita ingat lagi tiga folder kita. Folder public berisi halaman yang dibuka browser. Folder app berisi kode bersama, dan di dalamnya kita akan membuat empat berkas, yaitu koneksi, bantu, auth, dan awal. Folder database berisi SQL. Server hanya membuka folder public, jadi berkas di folder app dan berkas titik env tidak bisa diminta dari browser.

Buat berkas koneksi titik php di folder app. Bagian atas membaca titik env, lalu menghentikan program dengan pesan yang jelas kalau berkasnya belum ada. Fungsi db membuat sambungan PDO, dan kata static membuat sambungan itu hanya dibuat satu kali, walaupun fungsinya dipanggil berkali-kali. Ada tiga pengaturan penting. ERRMODE EXCEPTION membuat setiap kesalahan SQL menjadi error yang terlihat, bukan gagal diam-diam. FETCH ASSOC membuat hasil query berupa array dengan nama kolom. EMULATE PREPARES false membuat MySQL sendiri yang memisahkan perintah dari data.

Sekarang berkas bantu titik php. Fungsi q adalah fungsi yang paling sering kita pakai. Ia menerima SQL dengan tanda tanya sebagai tempat kosong, dan sebuah array berisi nilainya. Perintah prepare mengirim SQL-nya dulu, lalu execute mengirim nilainya secara terpisah. Cara ini disebut prepared statement. Karena perintah dan data dikirim terpisah, data dari pengguna tidak akan pernah dianggap sebagai perintah. Fungsi e mengamankan teks sebelum ditampilkan di HTML, supaya tulisan dari pengguna tidak berubah menjadi kode di halaman.

Fungsi bantu lainnya, seperti rupiah, tanggal, arahkan, pesan, dan token CSRF, pendek-pendek, jadi kuambil dari GitHub. Token CSRF adalah kode acak yang diselipkan di setiap form, untuk memastikan form itu benar-benar dikirim dari halaman kita sendiri. Berkas awal titik php hanya memanggil berkas-berkas lainnya, sehingga setiap halaman cukup menulis satu baris require.

Sekarang data contoh. Salin berkas isi contoh titik php dari GitHub ke folder database, lalu jalankan. Skrip ini membuat tujuh akun, dua belas alat, dan tiga puluh tujuh pinjaman, dan semua pinjaman itu dibuat lewat prosedur yang kita tulis di bab lima. Semua akun contoh memakai kata sandi rahasia satu dua tiga.

Sekarang kita ganti halaman percobaan dari bab satu dengan daftar alat sungguhan. Baris pertama memanggil awal titik php. Lalu fungsi q mengambil alat beserta nama kategorinya dengan JOIN. Di bagian HTML, perulangan foreach menampilkan setiap alat, dan semua teks dilewatkan ke fungsi e. Jalankan servernya, lalu buka di browser. Dua belas alat tampil, langsung dari database.

Cek kerjaan AI. Ini kode login yang sangat sering ditulis AI. Username dan kata sandi dari form disambung langsung ke dalam string SQL. Kalau diisi dengan data yang wajar, kode ini berjalan. Apa yang terjadi kalau seseorang mengetik tanda kutip di kolom username? Pikirkan dulu.

Kita buktikan. Di kolom username, kita ketik tanda kutip, lalu OR satu sama dengan satu, lalu dua tanda minus dan spasi. Kata sandinya kita isi sembarang. Kita masuk sebagai Bu Sari, sang admin, tanpa tahu kata sandinya. Tanda kutip tadi menutup teks username lebih awal. OR satu sama dengan satu selalu benar. Dua tanda minus membuat sisa perintahnya menjadi komentar, termasuk pemeriksaan kata sandi. Serangan ini bernama SQL injection. Dengan prepared statement, ketikan yang sama hanya dianggap sebagai username yang aneh, dan login-nya gagal. Commit dengan pesan kerangka PHP. Sekarang siapa pun bisa melihat daftar alat, padahal seharusnya login dulu. Kita pasang pintunya di bab berikutnya.
