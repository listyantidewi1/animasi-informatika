# F11.7 Model Jaringan dan Pengiriman Data — satu baris per potongan narasi: id<TAB>teks. Simpan suaranya sebagai <id>.mp3
intro1	Halo, kelas sebelas! Aku Kiko. Sinta mengirim foto ke laptop Dito lewat Wi-Fi, lalu mengirimnya ke server jauh. Apa yang terjadi di tengahnya? Setelah menonton, kamu bisa menjelaskan model jaringan dan mengirim data antarperangkat.
intro2	Tiga model hari ini: bentuk jaringan, atau topologi; peran perangkat, klien–server dan peer-to-peer; dan lapisan TCP/IP yang membungkus tiap pesan seperti surat berlapis amplop.
intro3	Episode ini melanjutkan D9.2 tentang jaringan lokal dan internet serta E.3 tentang router rumah. Kalau belum menontonnya, tonton dulu, ya.
play1	Main dulu. Tulis pesan. Masukkan ke amplop kecil bertuliskan nama aplikasi, lalu amplop sedang bertuliskan nomor pintu, lalu amplop besar bertuliskan alamat rumah, lalu tas kurir. Penerima membukanya lapis demi lapis: enkapsulasi.
play2	Lalu topologi dengan benang. Lima murid menjadi perangkat, benang menjadi kabel. Susun bentuk bintang dengan satu murid di tengah, lalu bentuk mesh yang semua saling terhubung. Guru menggunting satu benang: siapa yang terputus?
s1a	Topologi adalah bentuk sambungan. Bus: satu kabel bersama, murah, tetapi putus satu, putus semua. Bintang: semua ke satu switch, mudah dikelola, tetapi switch mati berarti semua mati. Mesh: saling terhubung, tahan putus, tetapi mahal.
s1b	Jaringan sekolah biasanya pohon: tiap lab berbentuk bintang ke switch-nya, switch-switch itu naik ke switch gedung, lalu ke router dan penyedia internet. Bertingkat, sehingga gangguan di satu lab tidak menjalar ke lab lain.
q1	Cek pemahaman. Di lab berbentuk bintang, switch pusatnya mati. Dampaknya: hanya satu komputer terputus, semua komputer di lab itu terputus, atau seluruh sekolah terputus? Pikirkan dulu.
q1a	Jawabannya: semua komputer di lab itu terputus, karena semuanya lewat switch itu. Lab lain aman: itulah gunanya pohon yang bertingkat.
s2a	Model peran pertama: klien–server. Klien meminta, server melayani: HP-mu meminta halaman, server web mengirimnya; begitu juga email dan gim daring. Terpusat dan mudah dikelola, tetapi kalau server padam, semua klien ikut terhenti.
s2b	Model kedua: peer-to-peer. Semua perangkat setara, saling meminta dan melayani: berbagi file langsung antar-HP, atau panggilan video yang mengalir langsung. Tahan karena tidak ada pusat, tetapi lebih sulit dikendalikan dan diamankan.
q2	Cek pemahaman. Kamu membuka situs sekolah di HP. Dalam model klien–server, HP-mu berperan sebagai: server, klien, atau router? Pikirkan dulu.
q2a	Jawabannya: klien. HP-mu meminta, server situs sekolah melayani. Satu perangkat bisa berganti peran: saat kamu membagikan file ke teman, HP-mu yang melayani.
s3a	Bagian dua. Empat lapisan TCP/IP: aplikasi, isi pesan dan aturannya seperti HTTP; transport, memecah pesan jadi segmen bernomor dengan port; internet, memberi alamat IP dan memilih jalur; link, menjadikannya sinyal di kabel atau Wi-Fi.
s3b	Enkapsulasi: pesan turun lapis demi lapis, tiap lapisan menambah header: port, IP, MAC. Di penerima, naik lapis demi lapis, tiap header dibuka. Tiap lapisan mengurus urusannya sendiri, seperti amplop yang tak perlu tahu isi surat.
q3	Cek pemahaman. Lapisan mana yang menambahkan alamat IP tujuan ke paket: aplikasi, transport, atau internet? Pikirkan dulu.
q3a	Jawabannya: lapisan internet. Transport menambah nomor port dan urutan segmen; link menambah alamat MAC untuk lompatan berikutnya.
s4a	Perjalanan di jaringan lokal: foto dari HP Sinta dipecah menjadi paket, dikirim lewat Wi-Fi ke titik akses, diteruskan switch ke laptop Dito berdasarkan alamat MAC-nya. Alamat IP lokal menunjuk laptopnya, port menunjuk aplikasinya.
s4b	Ke internet: router sekolah mengganti alamat lokal dengan alamat publik, paket melompat dari router ke router sampai server. Paket yang hilang tak mendapat tanda terima, dan TCP mengirimnya ulang. Ping dan traceroute memperlihatkannya.
q4	Cek pemahaman. Satu paket hilang di tengah jalan. Siapa yang menyadari dan meminta kirim ulang: lapisan aplikasi, TCP di lapisan transport, atau kabelnya sendiri? Pikirkan dulu.
q4a	Jawabannya: TCP di lapisan transport. Segmen bernomor dan tanda terima membuat yang hilang ketahuan dan dikirim ulang, tanpa aplikasi perlu tahu.
s5a	Kirim data sungguhan. Dua laptop di satu Wi-Fi: lihat alamat IP masing-masing, ping dari satu ke yang lain, lalu jalankan server web kecil: python minus m http titik server. Teman membuka alamatmu di browser: klien–server buatanmu sendiri.
s5b	Aturannya: hanya di jaringan yang diizinkan guru, tidak memindai atau menyadap perangkat orang lain, dan matikan server setelah selesai. Memahami jaringan adalah tanggung jawab; keamanannya kita dalami di episode berikutnya.
s6a	Sekarang giliranmu. Di halaman latihan: pembungkus paket, susun header tiap lapisan dengan urutan benar; penghubung topologi, pilih bentuk tiap kebutuhan, lihat dampak kabel putus; lalu pelacak lompatan, ikuti paket dari HP ke server.
s6b	Lalu di lab: gambar topologi jaringan sekolahmu dari pengamatan, catat alamat IP dan hasil ping, dan jalankan server web kecil untuk membagikan satu halaman ke teman. Itu model jaringan yang kamu pegang sendiri.
recap	Tiga hal untuk diingat. Satu: bintang di lab, pohon di sekolah, mesh tahan putus. Dua: klien meminta, server melayani; di peer-to-peer semua setara. Tiga: TCP/IP berlapis: aplikasi, transport, internet, link; dibungkus, lalu dibuka.
outro	Sampai jumpa di episode berikutnya: troubleshooting dan keamanan lanjut jaringan. Menjadi detektif jaringan: memilih uji diagnosis dan mempersempit penyebabnya. Sampai jumpa!
