Rencana 12 Bulan Menuju Software Engineer

Daftar periksa dari video “Mau Jadi Software Engineer di Era AI? Ini Peta Lengkapnya”. Pilih kolom yang paling mirip denganmu, lalu centang satu per satu.
1 · Fondasi
2 · Alat kerja
3 · Aplikasi utuh

5 · Magang dan kerja pertama

Mulai dari nol

Seperti Rani: kelas 11 SMA, belum pernah menulis kode
Bulan 1–3 · Fondasi dengan Python
  • Menulis langkah sehari-hari sampai tidak bisa disalahpahami
  • Variabel, percabangan, perulangan, fungsi, list, dictionary
  • Membaca pesan error sampai selesai
  • Tahu letak file dan memakai shortcut di laptop
Bulan 4–6 · Git dan dua program kecil
  • Memasang code editor dan mencoba terminal
  • Menyimpan pekerjaan dengan Git, mengunggah ke GitHub
  • Program kecil 1 selesai (misalnya game tebak angka)
  • Program kecil 2 selesai (misalnya kalkulator patungan)
Bulan 7–12 · Satu aplikasi web sederhana
  • Mengenal HTML, CSS, dan JavaScript dasar
  • Satu aplikasi web sederhana bisa dibuka orang lain
  • Menulis README untuk aplikasi itu
  • Memeriksa syarat masuk kampus atau jalur yang dituju

Sudah belajar di sekolah

Seperti Bayu: SMK RPL, sudah bisa membuat halaman web
Bulan 1–3 · Perkuat Git dan SQL
  • Menulis program kecil tanpa melihat contoh
  • Commit kecil dan rapi, branch, pull request
  • SQL: SELECT, JOIN, INSERT, UPDATE, DELETE
  • Merancang tabel untuk satu masalah nyata
Bulan 4–9 · Satu aplikasi utuh sampai deploy
  • Memilih satu jalur backend dan bertahan di sana
  • Punya login; tiap pengguna hanya melihat datanya
  • Data tersimpan di database
  • Menolak masukan yang salah
  • Punya beberapa tes otomatis
  • Deploy: bisa dibuka orang lain
Bulan 10–12 · Portofolio dan magang
  • README dengan tangkapan layar dan link demo
  • CV satu halaman, link GitHub di paling atas
  • Melamar ke minimal lima tempat magang

Sudah kuliah

Seperti Tegar: mahasiswa, belum punya aplikasi yang dipakai orang
Bulan 1–3 · Satu proyek nyata untuk orang nyata
  • Menemukan satu orang atau organisasi yang punya masalah
  • Menulis kebutuhan bersama mereka
  • Versi pertama dipakai oleh pengguna sungguhan
Bulan 4–9 · Menguji, merapikan, menulis README
  • Mencatat dan memperbaiki bug dari pengguna
  • Menambah tes untuk bagian yang paling penting
  • Riwayat commit menunjukkan proses kerja
  • README menjawab lima pertanyaan
  • Menulis bagian mana yang dibantu AI dan apa yang diperiksa
Bulan 10–12 · Wawancara dan magang
  • Berlatih live coding sambil berbicara
  • Menyiapkan cerita satu bug tersulit
  • Berlatih menjelaskan kode, dengan dan tanpa AI
  • Melamar magang

Tiga kebiasaan supaya tidak jadi operator AI (semua jalur)

  • Baca dan jelaskan. Setiap kode dari AI bisa kamu jelaskan baris demi baris.
  • Uji dengan masukan aneh. Nol, minus, teks kosong, dua orang menekan tombol bersamaan.
  • Kerjakan sebagian tanpa AI. Sesekali, buat fitur kecil tanpa bantuan sama sekali.

README yang baik menjawab

  • Aplikasi ini untuk apa? Bagaimana tampilannya?
  • Bagaimana cara menjalankannya?
  • Teknologi apa yang dipakai, dan kenapa?
  • Apa yang masih ingin diperbaiki?
